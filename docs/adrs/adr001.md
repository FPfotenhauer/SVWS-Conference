### Prompt 1 — Projektstruktur & Typen (Fundament)

```
Du entwickelst eine Browser-SPA mit Vue 3, TypeScript, Vite und Pinia.
Das Tool heißt "SVWS-Konferenzübersicht" und dient der digitalen
Notenkonferenz an Schulen.

Erstelle die vollständige Projektstruktur nach `npm create vue@latest`
mit folgenden Entscheidungen:
- TypeScript: Yes
- Pinia: Yes
- Vue Router: No
- ESLint + Prettier: Yes
- Vitest: Yes

Erstelle danach die Datei `src/types/svws.ts` mit folgenden Interfaces:

- Schueler { id, nachname, vorname, geschlecht? }
- Fach { id, bezeichnung, kuerzel }
- Note: { note: 1|2|3|4|5|6, noteText: string, fehlend: boolean } | null
- KonferenzKlasse { name, schueler: Schueler[], faecher: Fach[],
    noten: Record<SchuelerId, Record<FachId, Note>> }
- KonferenzLerngruppe { ... analog zu Klasse, zusätzlich kursart: string }
- SvwsExport { klassen: KonferenzKlasse[], lerngruppen: KonferenzLerngruppe[] }

Alle IDs als `string`. Exportiere alle Typen als named exports.
Keine Implementierung, nur Typdefinitionen.
```

### Prompt 2 — ZIP-Parser mit Typsicherheit

```
Kontext: Vue 3 + TypeScript + Vite SPA, Typen aus `src/types/svws.ts`
sind bekannt (s. Prompt 1).

Erstelle `src/parser/zipParser.ts` mit:

export async function parseZippedJson(
  input: ArrayBuffer | File
): Promise<SvwsExport>

Anforderungen:
- Nutze `fflate` (npm install fflate) zum Entpacken
- Unterstütze sowohl ArrayBuffer (aus fetch) als auch File (aus Input)
- Validiere nach dem Entpacken mit einer Funktion
  `validateSvwsExport(raw: unknown): SvwsExport`
  die einen sprechenden TypeError wirft wenn Pflichtfelder fehlen
- Nutze einen Type Guard `isSvwsExport(obj: unknown): obj is SvwsExport`
- Keine any-Casts außer an der Systemgrenze (raw JSON)
- Exportiere parseZippedJson und validateSvwsExport als named exports
- Unit-Tests mit Vitest für Validierungsfunktion (Minimal-Happy-Path
  + fehlende Pflichtfelder)
```

### Prompt 3 — Pinia Store

```
Kontext: Vue 3 + TypeScript + Vite + Pinia, Typen und zipParser bekannt.

Erstelle `src/stores/conferenceStore.ts` als Pinia Store
mit defineStore und Setup-Syntax (nicht Options API):

State:
- export: SvwsExport | null
- selectedKlasseId: string | null
- loading: boolean
- error: string | null

Actions:
- async loadFromUrl(baseUrl: string, token: string): Promise<void>
  → fetch, ArrayBuffer empfangen, parseZippedJson aufrufen
  → bei Fehler: error setzen, nicht werfen
- async loadFromFile(file: File): Promise<void>
  → parseZippedJson aufrufen
  → bei Fehler: error setzen, nicht werfen
- selectKlasse(id: string): void
- reset(): void

Getters:
- availableKlassen: computed → KonferenzKlasse[]
- currentKlasse: computed → KonferenzKlasse | null
- currentLerngruppen: computed → KonferenzLerngruppe[]

Alle Rückgabetypen explizit annotiert. Kein any.
```
