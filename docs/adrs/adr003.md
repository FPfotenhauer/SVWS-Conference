Gute Wahl — Vue passt sehr gut zu diesem Projekt, weil es sowohl als reines CDN-Script (ohne Build-Schritt) als auch mit Vite als vollwertige SPA funktioniert. Du kannst also klein anfangen und später skalieren.

Hier sind die konkreten Anpassungen zur Architekturbeschreibung:

### ADR-01 (aktualisiert): Framework-Entscheidung

**Vue.js** statt Svelte, aus folgenden Gründen:
- **CDN-Modus**: Vue 3 läuft per `<script src="https://unpkg.com/vue@3/dist/vue.global.js">` ohne jeden Build-Schritt — die App ist dann eine einzelne `index.html`
- **Migrations­pfad**: Wenn später Vite + SFC (`.vue`-Dateien) gewünscht werden, bleibt die Komponentenlogik nahezu identisch
- **Verbreitung im Schulumfeld**: Vue ist häufiger bekannt als Svelte, was die Wartbarkeit durch Dritte verbessert

### Zwei Deployment-Stufen

**Stufe 1 — Zero-Build (sofort einsetzbar):**
```
index.html   ← alles drin, Vue per CDN, fflate per CDN
```
Einfach per Doppelklick öffnen oder auf beliebigen Webserver legen.

**Stufe 2 — Vite + SFC (wenn die App wächst):**
```
src/
├── components/
│   ├── DataLoader.vue
│   ├── ClassView.vue
│   ├── GroupView.vue
│   └── PrintView.vue
├── stores/
│   └── conference.js   ← Pinia Store
├── composables/
│   ├── useRestLoader.js
│   └── useFileLoader.js
└── App.vue
```

**Prompt 1 — Vue CDN Grundgerüst:**
```
Erstelle eine einzelne index.html mit Vue 3 (CDN, Composition API)
und fflate (CDN). Die App hat zwei Ansichten (kein Router nötig):
1. Ladeansicht (REST-URL oder ZIP-Upload)
2. Konferenzansicht (Klassen-Tabelle)
Zustandswechsel über eine reactive() Variable `currentView`.
Kein Build-Schritt, keine node_modules.
```

```
Erstelle einen Pinia-Store `useConferenceStore` mit:

- action: loadFromZip(arrayBuffer)
- action: loadFromUrl(baseUrl, token)
- getter: currentClassData → { students[], subjects[], grades{} }
TypeScript optional, aber nicht zwingend.
```
